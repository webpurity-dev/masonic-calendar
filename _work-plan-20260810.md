# Work Plan - Full-Bleed Front and Back Covers

**Approval status:** Approved by user on 2026-08-10

## Configuration Strategy

- Set `page_margins.page_size` in `document/master_v1.yaml` to `111mm 154mm`.
- Treat the outer page as A6 (`105mm 148mm`) plus 3mm bleed on every edge.
- Add 3mm to ordinary page margins so existing content remains positioned relative to the A6 trim area.
- Keep cover-specific full-bleed styling in the cover templates, as explicitly approved.

## Files Affected

- `document/master_v1.yaml`: configure bleed-page dimensions and trim-relative ordinary margins.
- `document/templates/cover-front.html`: center and cover the complete bleed page.
- `document/templates/cover-back.html`: center and cover the complete bleed page and select a zero-margin named page.
- `src/MasonicCalendar.Core/Renderers/SchemaPdfRenderer.cs`: make multi-section HTML portable and show the A6 trim boundary 3mm inside the bleed page.
- `_work-plan-20260810.md`: record scope, decisions, validation, and outcome.

## Scope

- Front and back cover images fill the `111mm x 154mm` media page.
- Images use centered `object-fit: cover` cropping.
- The intended trim remains exactly A6, inset 3mm from every media edge.
- Interior content retains its current distance from the A6 trim edges.

## Approach

1. Configure the larger bleed page and trim-relative interior margins.
2. Make both cover wrappers full-page and their images fill the wrapper.
3. Assign the back cover to a named zero-margin page.
4. Build and render HTML, then inspect generated page and cover CSS.

## Risks

- Chromium/Puppeteer does not emit a formal PDF `TrimBox`; the printer must set A6 trim metadata during prepress.
- `object-fit: cover` may crop image edges when source and output aspect ratios differ.
- Cover-specific styling is hardcoded in templates by explicit user choice.

## Rollback Strategy

- Revert the three implementation files using git history or restore their previous values.
