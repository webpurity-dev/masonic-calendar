# Work Plan - Dorset Masonic Halls Unit Ordering

## Configuration Strategy

Add a section-level YAML property to `dorset_masonic_halls`:

```yaml
unit_type_sort_priority: ["Craft", "RA"]
```

The locations renderer will use this list as ordered priority groups. Units within each configured group will be sorted by number. Unit types not listed will follow, also sorted by number. Locations sections without this property will retain the current number-only ordering.

Hardcoding `Craft` and `RA` in C# was considered and rejected because the project is configuration-driven and the priority may vary by document.

## Files Affected

1. `document/master_v1.yaml`
   - Add `unit_type_sort_priority` to the `dorset_masonic_halls` section.
   - This is the document-specific source of the requested ordering.

2. `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
   - Add `UnitTypeSortPriority` to `SectionConfig` so YamlDotNet can deserialize the new section property.

3. `src/MasonicCalendar.Core/Renderers/SectionRenderers/LocationSectionRenderer.cs`
   - Sort each hall's units by configured unit-type priority, then by unit number.
   - Assign all unlisted unit types the fallback priority after configured types.
   - Preserve number-only ordering when no priority is configured.

4. `_work-plan-20260812.md`
   - Record scope, decisions, validation, and approval status.

## Scope

Only unit ordering within each Dorset Masonic Halls location page is affected. Hall ordering, filtering, two-column distribution, labels, and templates remain unchanged.

## Approach

1. Extend `SectionConfig` with an optional list of unit types used for sort priority.
2. Configure `Craft` first and `RA` second on `dorset_masonic_halls`.
3. Build a case-insensitive priority lookup in `LocationSectionRenderer`.
4. Order by priority and then `SchemaUnit.Number`.
5. Render only the `dorset_masonic_halls` section and inspect each hall's rendered unit sequence.

## Validation

Run:

```powershell
cd src/MasonicCalendar.Console
dotnet run -- -template master_v1 -output html -section dorset_masonic_halls
```

Verify in the generated HTML that, within each hall:

1. Craft units appear first in ascending number order.
2. RA units appear second in ascending number order.
3. All other unit types follow in ascending number order.

## Risks

- Source data must use unit type values matching `Craft` and `RA`; matching will be case-insensitive.
- Column balancing preserves the sorted sequence vertically, so a priority group may continue in the second column.
- Duplicate unit numbers retain LINQ's stable source order within the same priority group.

## Rollback

Remove the YAML property, the `SectionConfig` property, and the renderer priority ordering. Existing number-only behavior will then be restored.
