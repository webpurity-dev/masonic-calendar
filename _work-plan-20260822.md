# Work Plan - Configurable Officers Page Break

## Configuration Strategy
- Add an optional section-level `break_before_officers` boolean for `type: "list_officers"` sections.
- Store the setting in `document/master_v1.yaml` when an order needs it; do not hardcode order names or section IDs.
- Default to `false`, preserving every existing section until explicitly enabled.
- Capability-only scope: do not enable the setting for any section in this change.

Approval status: Initial implementation and stylesheet amendment approved by user on 2026-08-22.

Implementation status: Complete.
- `dotnet build .\MasonicCalendar.sln` passed with 0 warnings and 0 errors.
- Targeted `mark_officers` HTML render completed successfully.
- Browser verification: district heads are on Paged.js page 1; officers heading and officers table begin on page 2.

## Files Affected
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add `SectionConfig.BreakBeforeOfficers`  so YamlDotNet maps `break_before_officers`.
- `src/MasonicCalendar.Core/Renderers/SectionRenderers/ProvincialOfficersSectionRenderer.cs`
  - Pass the configured value into the Scriban model.
- `document/templates/_data-driven/list-officers.html`
  - Conditionally apply the officers page-break class at the district/officers boundary.
- `document/templates/print.css`
  - Define the Paged.js-parsed forced-break class used by the template.

`document/master_v1.yaml` will not change in this capability-only implementation.

## Scope
- Apply only to `list_officers` rendering.
- Place the forced break after the heads/district content and immediately before the officers heading.
- Keep the officers heading and officers table in the same conditional block.
- Preserve current output when `break_before_officers` is absent or `false`.

## Approach
1. Add the strongly typed optional setting with a `false` default.
2. Expose it to the existing Scriban template model.
3. Emit a conditional class at the requested district/officers boundary.
4. Define the forced break in `print.css` so Paged.js sees it while parsing stylesheet rules.
5. Build the solution and render `mark_officers`; verify district heads and officers occupy different `.pagedjs_page` elements.

## Local Hypothesis And Check
- Hypothesis: the renderer already owns all section-level template inputs, so passing one boolean and conditionally wrapping the officers block will force the requested internal page boundary without affecting section-level `override_break_before` behavior.
- Disconfirming check: a solution build fails after adding the property/model field, indicating the configuration or renderer integration is incomplete.

## Risks
- Browser pagination engines can differ in support for modern versus legacy break properties; emitting both properties minimizes this risk.
- A break before an empty officers block would create an unwanted page, so the wrapper will only render around visible officer content.

## Investigation Result
- The generated HTML contains the configured inline rule, and Chromium computes it as `break-before: page`/`break-after: page`.
- Paged.js nevertheless keeps the district heads and officers heading on page 1.
- Existing working page-boundary rules are parsed from `print.css`; the amendment moves this rule into that same mechanism.

## Rollback
- Revert the three focused implementation-file changes and this plan file.

# Work Plan - Configurable Unit Content Page Breaks

## Configuration Strategy
- Add `ui_preferences.unit_page_breaks` to `document/master_v1.yaml` with two named rules:
  - `before_joining_past_masters`: minimum rendered officers `25`, minimum past masters `19`, minimum joining past masters `4` (equivalent to `> 3`).
  - `before_members`: maximum rendered officers `24`, maximum past masters `18`, maximum joining past masters `3`.
- Use inclusive `min_*` and `max_*` YAML properties so every threshold remains configuration-driven and the comparison behavior is explicit.
- Count rendered officers after `hide_not_appointed` filtering and exclusion of `Office == "0"`; count the rendered past-master and joining-past-master collections.
- If a rule is absent, it does not add a page break. Mixed count combinations that match neither complete rule retain natural pagination.

Approval status: Superseded by the per-unit CSV page-break flag plan below.

## Files Affected
- `document/master_v1.yaml`
  - Store both approved rule blocks under `ui_preferences.unit_page_breaks`.
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add strongly typed YAML models for the two named rule blocks and their optional min/max thresholds.
- `src/MasonicCalendar.Console/Program.cs`
  - Pass the loaded unit-page-break configuration to `UnitModelBuilder` using the existing UI-preferences setup path.
- `src/MasonicCalendar.Core/Renderers/Utilities/UnitModelBuilder.cs`
  - Evaluate each complete rule against visible collection counts and expose `pageBreaks.beforeJoiningPastMasters` and `pageBreaks.beforeMembers` to Scriban.
- `document/templates/_data-driven/unit-page.html`
  - Conditionally add the existing stylesheet-backed `page-break-before` class to the joining-past-masters and both members section variants.
- `src/MasonicCalendar.Tests/UnitModelBuilderPageBreakTests.cs`
  - Add focused boundary and non-match tests for both configured rules, including filtered/placeholder officer rows.

## Scope
- Apply only to unit pages rendered by `_data-driven/unit-page.html`.
- Break immediately before the joining-past-masters heading when all three first-rule conditions match.
- Break immediately before members when all three second-rule conditions match, including grouped-member layouts.
- Do not alter section-to-section or unit-to-unit page breaks.
- Do not add a generic expression engine or hardcoded threshold fallback.

## Approach
1. Add nullable typed threshold models under `UiPreferences` and configure the two rules in YAML.
2. Wire the configuration through the existing `Program.cs` initialization path.
3. Evaluate rules once per unit in `UnitModelBuilder` using rendered counts and AND semantics.
4. Expose only the resulting break booleans to Scriban.
5. Apply the existing `page-break-before` CSS class at the requested content boundaries.
6. Run focused tests, build the solution, and render representative matching units for HTML inspection.

## Local Hypothesis And Check
- Hypothesis: Paged.js already honors the stylesheet-defined `.page-break-before` class, so calculating two booleans in the model and conditionally adding that class will create stable internal unit-page boundaries without embedding thresholds in the template.
- Disconfirming check: a focused template render with matching synthetic counts does not contain `page-break-before` on the expected section, or a representative Paged.js render leaves that section on the preceding page.

## Validation
- Automated tests at and immediately below each threshold, plus mixed-condition non-matches.
- A test proving hidden/placeholder officers do not contribute to the configured officer count.
- `dotnet build .\MasonicCalendar.sln`.
- Representative single-unit HTML renders for each matched rule, followed by inspection of generated classes and Paged.js page placement.

## Risks
- A unit can match neither rule when counts cross thresholds in mixed directions; this is intentional because each rule uses AND semantics.
- Static configuration on `UnitModelBuilder` can leak between tests; tests will reset the configured rules after each case.
- Forced breaks may leave unused space on the preceding page, which is the requested tradeoff for distributing unit content.

## Rollback
- Revert the six files listed above and this plan section. Existing rendering behavior then returns because no default thresholds are introduced.
