# Work Plan - Configurable Officers Page Break

## Configuration Strategy
- Add an optional section-level `break_before_officers` boolean for `type: "list_officers"` sections.
- Store the setting in `document/master_v1.yaml` when an order needs it; do not hardcode order names or section IDs.
- Default to `false`, preserving every existing section until explicitly enabled.
- Capability-only scope: do not enable the setting for any section in this change.

Approval status: Initial implementation and stylesheet amendment approved by user on 2026-08-22.

Implementation status: Complete.
- `dotnet build .\MasonicCalendar.sln` passed with 0 warnings and 0 errors.
- Targeted `mark_officers` HTML render completed successfully.
- Browser verification: district heads are on Paged.js page 1; officers heading and officers table begin on page 2.

## Files Affected
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add `SectionConfig.BreakBeforeOfficers` so YamlDotNet maps `break_before_officers`.
- `src/MasonicCalendar.Core/Renderers/SectionRenderers/ProvincialOfficersSectionRenderer.cs`
  - Pass the configured value into the Scriban model.
- `document/templates/_data-driven/list-officers.html`
  - Conditionally apply the officers page-break class at the district/officers boundary.
- `document/templates/print.css`
  - Define the Paged.js-parsed forced-break class used by the template.

`document/master_v1.yaml` will not change in this capability-only implementation.

## Scope
- Apply only to `list_officers` rendering.
- Place the forced break after the heads/district content and immediately before the officers heading.
- Keep the officers heading and officers table in the same conditional block.
- Preserve current output when `break_before_officers` is absent or `false`.

## Approach
1. Add the strongly typed optional setting with a `false` default.
2. Expose it to the existing Scriban template model.
3. Emit a conditional class at the requested district/officers boundary.
4. Define the forced break in `print.css` so Paged.js sees it while parsing stylesheet rules.
5. Build the solution and render `mark_officers`; verify district heads and officers occupy different `.pagedjs_page` elements.

## Local Hypothesis And Check
- Hypothesis: the renderer already owns all section-level template inputs, so passing one boolean and conditionally wrapping the officers block will force the requested internal page boundary without affecting section-level `override_break_before` behavior.
- Disconfirming check: a solution build fails after adding the property/model field, indicating the configuration or renderer integration is incomplete.

## Risks
- Browser pagination engines can differ in support for modern versus legacy break properties; emitting both properties minimizes this risk.
- A break before an empty officers block would create an unwanted page, so the wrapper will only render around visible officer content.

## Investigation Result
- The generated HTML contains the configured inline rule, and Chromium computes it as `break-before: page`/`break-after: page`.
- Paged.js nevertheless keeps the district heads and officers heading on page 1.
- Existing working page-boundary rules are parsed from `print.css`; the amendment moves this rule into that same mechanism.

## Rollback
- Revert the three focused implementation-file changes and this plan file.

# Work Plan - Configurable Officer Name Suffix Emphasis

## Configuration Strategy
- Add an optional section-level `bold_officer_name_suffix` boolean for `type: "list_officers"` sections.
- Store the setting in `document/master_v1.yaml`; default to `false` so all other orders retain their current rendering.
- Enable it only for these six sections:
  - `craft_provincial_officers`
  - `craft_promotions`
  - `craft_appointments`
  - `ra_provincial_officers`
  - `ra_promotions`
  - `ra_appointments`
- Apply formatting only to names in the officers table, not heads, deputy heads, or district heads.

Approval status: Approved by user on 2026-08-22.

Implementation status: Complete. `dotnet build .\MasonicCalendar.sln` passed with 0 warnings and 0 errors.

## Files Affected
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add `SectionConfig.BoldOfficerNameSuffix` for YAML mapping.
- `src/MasonicCalendar.Core/Renderers/SectionRenderers/ProvincialOfficersSectionRenderer.cs`
  - When enabled, split each officer name once at the first comma into a normal name and rank suffix.
  - Keep structured text fields rather than generating HTML in C#.
- `document/templates/_data-driven/list-officers.html`
  - Render the comma normally and the non-empty suffix in `<strong>`.
- `document/master_v1.yaml`
  - Enable the setting on the six agreed Craft and Royal Arch regional officer sections only.

## Scope
- Example: `T Green, PAGDC` renders as `T Green, ` followed by bold `PAGDC`.
- Split only at the first comma; any later commas remain part of the bold suffix.
- Names without a comma render exactly as before.
- Preserve current behavior for UGLE, SGC, grand-officer, and all other order sections.

## Approach
1. Add the strongly typed section setting with a `false` default.
2. Build a structured officers template model containing the original name plus optional prefix and suffix.
3. Conditionally render the structured name only when the setting is enabled and a suffix exists.
4. Enable the setting on the six approved section IDs.
5. Build the solution as the agreed validation.

## Local Hypothesis And Check
- Hypothesis: `ProvincialOfficersSectionRenderer` is the single owner of all six regional lists, so splitting names in its template model keeps the behavior scoped and avoids changing CSV/domain data.
- Disconfirming check: a solution build or Scriban template parse failure would show that the model/template contract is incomplete.

## Risks
- A comma that is part of a person’s name rather than a rank will still mark the remainder as a suffix; the feature is opt-in only for the agreed datasets.
- Whitespace around the comma must be normalized so output does not contain doubled spaces.

## Rollback
- Remove the six YAML flags and revert the loader, renderer, and template changes.
