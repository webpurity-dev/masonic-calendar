# Work Plan - Configurable Member Initial Compaction

## Configuration Strategy
- Add `ui_preferences.member_name_initials_compact_threshold: 22` to `document/master_v1.yaml`.
- Deserialize the value as a nullable integer. When omitted or null, initial compaction is disabled; there is no hardcoded fallback.
- Apply strict `name.Length > threshold` behavior after existing name cleanup.

Approval status: ⏳ Awaiting user approval.

## Files Affected
- `document/master_v1.yaml`
  - Store the member-name threshold under the existing `ui_preferences` block.
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add the nullable `UiPreferences.MemberNameInitialsCompactThreshold` property for YAML deserialization.
- `src/MasonicCalendar.Console/Program.cs`
  - Pass the loaded threshold to `UnitModelBuilder` through the existing UI-preferences initialization path.
- `src/MasonicCalendar.Core/Renderers/Utilities/UnitModelBuilder.cs`
  - Add the configured threshold and compact spaces only within the initials portion of long regular-member names.
  - Leave grouped members and all other person types unchanged.
- `src/MasonicCalendar.Tests/UnitModelBuilderMemberNameTests.cs`
  - Verify names above the configured threshold compact initials, names at/below it remain unchanged, missing configuration disables compaction, and grouped members remain unchanged.

## Scope
- Apply only to regular, ungrouped member output in `memberColumns`.
- Preserve the comma and one following space: `Long-Surname, B R O` becomes `Long-Surname, BRO` when its cleaned length is greater than the configured threshold.
- Keep the comparison strictly greater than the configured value.
- Do not alter officers, past masters, joining past masters, honorary members, or grouped members.

## Approach
1. Add the nullable YAML-backed property to `UiPreferences` and configure it as `22` in the master layout.
2. Assign the loaded value to a nullable static configuration property on `UnitModelBuilder`.
3. Add a focused helper that first calls `TextCleaner.CleanName`, then removes spaces only after the first comma when the configured threshold is exceeded.
4. Use that helper only in `SplitMembersIntoColumns`; retain direct `CleanName` usage in `SplitGroupMembers`.
5. Add focused tests and run them immediately after the first implementation edit.
6. Build the solution and render unit 417 to HTML for representative output validation.

## Local Hypothesis And Check
- Hypothesis: `memberColumns` is the only rendered model for regular members, while `groupedMembers` has a separate builder, so changing only `SplitMembersIntoColumns` scopes the behavior correctly.
- Disconfirming check: focused model tests show grouped output changing, a boundary name compacting unexpectedly, or the YAML value failing to deserialize and reach `UnitModelBuilder`.

## Risks
- Static configuration can leak between tests; each test will restore the previous configured threshold.
- Names without a comma cannot identify an initials segment and must remain unchanged.
- The example `Acres-Debenham, B R O` is 21 characters and therefore remains unchanged with a strict threshold of `22`, as previously confirmed.

## Validation

- `dotnet build .\MasonicCalendar.sln`.
- `dotnet run -- -template master_v1 -output html -unit 417`, followed by inspection of the generated member output.

## Rollback
