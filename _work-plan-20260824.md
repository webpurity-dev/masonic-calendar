# Work Plan: Per-Order Provincial and Grand Rank Display

**Date:** 24 August 2026  
**Approval status:** ✅ Approved

## Configuration Strategy

Add a configuration-driven exception list under `ui_preferences.rank_display` in `document/master_v1.yaml`.

Recommended shape:

```yaml
display_provincial_and_grand_rank:
  - unit_type: "Craft"
    provincial_ranks:
      - "DepProvGM"
      - "AsstProvGM"
      - "PProvGM"
      - "PDepProvGM"
      - "PAsstProvGM"
  - unit_type: "RA"
    provincial_ranks:
      - "DepGSupt"
      - "2ndProvGPrin"
      - "3rdProvGPrin"
      - "PGSupt"
      - "PDepGSupt"
      - "P2ndProvGPrin"
      - "P3rdProvGPrin"
```

`Craft` and `RA` are recommended because they match the actual `SchemaUnit.UnitType` values loaded from the CSV. Matching will be case-insensitive. No rank names or order rules will be hardcoded in C#.

When the current unit type and provincial rank match a configured entry:

- Past masters and joining past masters display `provincial_rank [date], grand_rank [date]`.
- Honorary members display `provincial_rank, grand_rank`, respecting the existing `show_dates.honorary_members: false` setting.
- If either rank is absent, display the available rank only.
- Unlisted unit types and provincial ranks retain the existing priority-based single-rank display.
- Officers and regular members are unchanged.

   - Store the per-order provincial-rank exception lists under the existing rank display configuration.

   - Select the configured exception by `SchemaUnit.UnitType`.
   - Build provincial-first, grand-second display text for past masters, joining past masters, and honorary members only when configured.
   - Preserve existing fallback and date behavior elsewhere.

4. `src/MasonicCalendar.Tests/UnitModelBuilderRankDisplayTests.cs`
   - Verify configured RA paired ranks and dates.
   - Verify the rule applies to past masters, joining past masters, and honorary members.
   - Verify unlisted ranks and unit types retain grand-rank priority.
   - Restore static configuration after each test to prevent cross-test leakage.

No template change is expected because `_data-driven/unit-page.html` already renders `display_rank`.

## Scope

- Apply only to past masters, joining past masters, and honorary members.
- Use exact provincial-rank matching with case-insensitive comparison.
- Keep rank output order as provincial rank, then grand rank.
- Keep existing date configuration and all other rank priority behavior.

## Approach

1. Extend the YAML-bound `RankDisplay` model with a list of per-unit-type rules.
2. Add the Craft and RA rules to `master_v1.yaml`.
3. Pass the current unit type into the local rank formatting decision inside `UnitModelBuilder`.
4. Reuse one formatter for dates so paired ranks have consistent square-bracket formatting.
5. Add focused unit tests before rendering the requested proof unit.
