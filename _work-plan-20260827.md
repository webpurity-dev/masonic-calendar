# Work Plan - Joining Past Masters Unit Display

**Date:** 2026-08-27  
**Approval status:** Approved by user through supplied configuration  
**Implementation status:** Completed and validated

## Configuration Strategy

Use the supplied document-level configuration in `ui_preferences`:

```yaml
joining_past_masters_display:
  joining_units_threshold: 3
  hide_joining_units: false
  consolidate_joining_units: true
```

For a joining past master whose unit count exceeds the threshold:

- `hide_joining_units: true` returns an empty units cell and takes precedence.
- Otherwise, `consolidate_joining_units: true` returns the existing `"X unit(s)"` display.
- When both flags are false, the complete unit list is displayed.
- At or below the threshold, the complete unit list is always displayed.

- `src/MasonicCalendar.Core/Renderers/Utilities/UnitModelBuilder.cs` - replace the hardcoded threshold with configured behavior.
- `src/MasonicCalendar.Tests/UnitModelBuilderJoiningUnitsDisplayTests.cs` - cover threshold boundary, consolidation, hiding, full-list behavior, and YAML loading.

## Extension - Exceeded Joining Units

**Requested and approved:** 2026-08-27  
**Implementation status:** Completed and validated

### Configuration Contract

```yaml
joining_past_masters_display:
  joining_units_threshold: 2
  hide_exceeded_joining_units: true
  consolidate_exceeded_joining_units: true
  consolidate_text: "X unit(s)"
```

- At or below the threshold, display the complete unit list.
- Above the threshold with `hide_exceeded_joining_units: true`, display only the first threshold units; this takes precedence.
- Above the threshold with hiding disabled and consolidation enabled, replace `X` in `consolidate_text` with the total unit count.
- With both behaviors disabled, display the complete unit list.

# Work Plan - Break Before Joining Past Heads

**Requested:** 2026-08-27  
**Approval status:** Approved by user  
**Implementation status:** Complete

## Configuration Strategy

Use the new shared `units.csv` boolean column through each order's existing YAML field mapping:

```yaml

  csv_column: "Break Before Joining Member"
  type: "bool"
```

The CSV header is currently singular (`Break Before Joining Member`) and must be matched exactly. The C# property and Scriban model key will use `BreakBeforeJoiningMembers` / `breakBeforeJoiningMembers` to describe the table behavior clearly.

## Files Affected

- `src/MasonicCalendar.Core/Domain/SchemaUnit.cs` - add the boolean unit property, defaulting to false.

The flag affects only the Joining Past Heads table for the corresponding unit. It does not force a break when that table has no rows and does not alter the existing Members page-break flag.

2. Expose the value in `UnitModelBuilder`.
3. Add the conditional `page-break-before` class to the existing Joining Past Heads table wrapper.
4. Add the field mapping beside `BreakBeforeMembers` in every unit data source.
5. Extend focused loader/model/template tests and run them immediately after implementation.
6. Run the full test suite.
7. Render Craft unit 3366, whose new CSV flag is `TRUE`, and confirm its Joining Past Masters heading starts in an element with `page-break-before`.
