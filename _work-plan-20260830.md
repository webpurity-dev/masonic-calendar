# Work Plan - Chunk Joining Past Masters Tables

**Date:** 2026-08-30
**Approval status:** Approved by user on 2026-08-30
**Implementation status:** Complete

## Configuration Strategy

Add the row limit to the existing document-level display configuration rather than hardcoding it in C# or Scriban:

```yaml
ui_preferences:
  joining_past_masters_display:
    rows_per_table: 46
```

A positive value chunks the rendered Joining Past Masters list into tables of that size. A missing, zero, or negative value preserves the current single-table behavior.

## Files Affected

- `document/master_v1.yaml`
  - Set `ui_preferences.joining_past_masters_display.rows_per_table` to `46`.
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Deserialize the optional row limit beside the existing Joining Past Masters display settings.
- `src/MasonicCalendar.Core/Renderers/Utilities/UnitModelBuilder.cs`
  - Build the rendered Joining Past Master rows once and split them into configured table chunks.
- `document/templates/_data-driven/unit-page.html`
  - Render one complete table per chunk.
  - Preserve the existing configured break before the first table.
  - Force every later chunk onto a new page and repeat the column headings.
- `src/MasonicCalendar.Tests/UnitModelBuilderJoiningUnitsDisplayTests.cs`
  - Verify YAML loading, 46-row boundaries, remainder chunks, disabled chunking, ordering, and no lost/duplicated rows.
- `_work-plan-20260830.md`
  - Record configuration ownership, scope, validation, and approval.

## Scope

- Apply only to Joining Past Masters tables on unit pages.
- Keep units with 46 or fewer Joining Past Masters as one table with no added internal page break.
- For larger lists, render rows `1-46`, `47-92`, and so on in separate tables; each table after the first begins on a new page.
- Preserve row order, headings, rank formatting, joining-unit formatting, data IDs, and CSV/export counts.
- Do not add dummy member rows or modify source CSV data.

## Approach

1. Add and load the optional `rows_per_table` configuration.
2. Refactor the current Joining Past Master model projection into a local rendered-row list.
3. Chunk that list while retaining the existing flat `joiningPastMasters` model for compatibility.
4. Render `joiningPastMasterTables`; apply `page-break-before` to chunks after index zero.
5. Repeat the real table header for every chunk.
6. Run focused tests and render the three affected units.

## Local Hypothesis And Check

- Hypothesis: explicit 46-row tables remove Paged.js discretion at the failing boundary, so Chromium no longer clips the first continuation row.
- Disconfirming check: a generated model has chunk sizes other than `46, 46, remainder`, row IDs are missing/duplicated/out of order, or the PDF still omits row 47 at the top of a continuation page.

## Impact Audit

The current row-count export identifies exactly three affected units:

- Craft 3366 - 118 Joining Past Masters (`46 + 46 + 26`).
- Craft 9508 - 52 Joining Past Masters (`46 + 6`).
- Royal Arch 3366 - 76 Joining Past Masters (`46 + 30`).

All other current units retain one Joining Past Masters table.

## Risks

- Fixed row counts assume the current font and row density; configuration keeps the threshold adjustable later without another code change.
- A row with unusually wrapped content may still be taller, but explicit table boundaries prevent the known first-row continuation clipping.
- Retaining the flat model avoids breaking tests or consumers that inspect `joiningPastMasters` directly.

## Rollback Strategy

Remove `rows_per_table`, revert model chunking and template iteration, and remove the focused tests. Source CSV data and existing page-break flags remain unchanged.
