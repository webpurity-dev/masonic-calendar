# Work Plan - Heading-Aware Officer Table Sizes

**Date:** 2026-08-30
**Approval status:** Approved by user on 2026-08-30
**Implementation status:** Complete

## Configuration Strategy

Replace the single order-officer row limit with two YAML-owned limits:

```yaml
ui_preferences:
  order_officers_display:
    rows_per_table_with_heading: 30
    rows_per_table_without_heading: 36
```

`heading` means the full `heading1` block shares the first officer-table page. The smaller `officers_heading` remains compatible with the 36-row limit.

## Files Affected

- `document/master_v1.yaml`
  - Replace `rows_per_table` with the two approved limits.
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Deserialize `RowsPerTableWithHeading` and `RowsPerTableWithoutHeading`.

  - Select the first-table limit from actual page-break behavior and use the no-heading limit for continuation tables.
- `src/MasonicCalendar.Tests/ProvincialOfficersSectionRendererTests.cs`
  - Verify configuration loading, asymmetric chunk boundaries, row order/completeness, and relevant section conditions.
- `_work-plan-20260830.md`
  - Record approval, implementation, and validation outcomes.

No template, factory, executive-officer renderer, or CSV changes are required.

## Behavior

- First table uses 30 rows only when `display_officers_only` is false and `break_before_officers` is false, because `heading1` shares that page.
- First table uses 36 rows when `display_officers_only` is true or `break_before_officers` is true, because `heading1` is absent from that page.
- Every continuation table uses 36 rows because continuation pages do not repeat `heading1`.
- Missing or non-positive limits preserve one table rather than introducing hardcoded fallback values.

Examples:

- `grand_officers`, 58 rows: `30 + 28`.
- `craft_provincial_officers`: first table can contain 36 rows because `break_before_officers: true` separates it from `heading1`.
- `craft_promotions`, 109 rows: `36 + 36 + 36 + 1` because `display_officers_only: true` suppresses `heading1`.

## Local Hypothesis And Check

- Hypothesis: selecting the first chunk size from whether `heading1` shares its page preserves Grand Officers spacing while using the available height on page-separated officer lists.
- Disconfirming check: Grand Officers does not split `30 + 28`, no-heading lists do not use 36, continuation chunks use 30, or any officer is missing, duplicated, or reordered.

## Validation

1. Run focused tests for `ProvincialOfficersSectionRendererTests`.
2. Run the full solution test suite.
3. Render `grand_officers`, `craft_provincial_officers`, and `craft_promotions` to HTML.
4. Confirm expected table counts, chunk sizes, and forced continuation breaks.
5. Render affected sections to PDF and confirm page counts and no clipped rows.

## Risks And Rollback

- `heading1` may contain an empty string; page-sharing is therefore based on rendered section behavior plus a non-empty value.
- Rollback restores the single `rows_per_table` property and the current uniform chunk helper.
