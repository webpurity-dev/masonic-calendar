**Date:** 2026-08-31  
**Approval status:** Approved by user on 2026-08-31  
**Implementation status:** Complete

## Configuration Strategy

Option A (recommended): add a crop-mark configuration block under `page_margins` in `document/master_v1.yaml`. It will contain the trim inset (`3mm`), mark length, stroke width, and colour. The renderer will consume those values only when `-showbleeds` is supplied.

Option B: restore crop marks with fixed values in `SchemaPdfRenderer.cs`. This is a smaller single-file change, but would hardcode print-production values and requires explicit approval under the repository rules.

## Files Affected (Option A)

- `document/master_v1.yaml`
  - Store the A6 trim/bleed crop-mark values.
- `src/MasonicCalendar.Core/Domain/PageMargins.cs`
  - Add the YAML-deserializable configuration class and attach it to `PageMargins`.
- `src/MasonicCalendar.Core/Renderers/SchemaPdfRenderer.cs`
  - Generate black crop marks at all four trim corners from configuration when `-showbleeds` is enabled, replacing the current dashed visualization-only output.
- `_work-plan-20260831.md`
  - Record the approved scope and completed validation.

## Scope

- Preserve the existing 111 mm x 154 mm media page and 105 mm x 148 mm A6 trim size.
- Make `-showbleeds` render four black L-shaped crop marks around the 3 mm trim boundary on every Paged.js page.
- Test with `-section static` in HTML first; do not change normal output without `-showbleeds`.

## Approach

1. Define the configured crop-mark measurements and colour in the master YAML. Completed.
2. Deserialize them with the existing layout model. Completed.
3. Replace `GenerateBleedVisualizationCss()` with a configuration-driven CSS generator that places all four inverted marks per rendered page. Completed.
4. Generate the static-section proof and verify the generated CSS includes all four marks at the configured 3 mm inset. Completed: 31 paginated proof pages rendered; browser inspection confirmed the configured 3 mm inset, 5 mm mark length, four corners, outward-facing orientation, right-hand marks mirrored from the left, and a bottom-left mark vertically mirrored from the top-left mark.

## Risks

- Paged.js pseudo-element stacking and overflow rules can hide marks. The implementation will use the existing page/pagebox elements and high stacking order.
- Browser proof rendering depends on Paged.js loading from its CDN; the generated CSS check remains a deterministic first validation.

## Rollback Strategy

Remove the crop-mark configuration and renderer changes. The `-showbleeds` behavior then returns to its current dashed-boundary visualization.

# Work Plan - Full-Bleed Back Cover

**Date:** 2026-08-31  
**Approval status:** Approved by user on 2026-08-31  
**Implementation status:** Complete

## Configuration Strategy

Add a named page style to the `back_cover` section in `document/master_v1.yaml`. The section will reference a configured page-style name rather than hardcoding the back-cover identity or its print behavior in a template.

The renderer will generate an `@page` rule for that named style with zero margins and an empty footer, then apply it only to the section wrapper. This gives the back-cover image the same 111 mm x 154 mm full-bleed media area as the front cover while suppressing its page number.

## Files Affected

- `document/master_v1.yaml`
  - Assign the configured full-bleed page style to `back_cover`.
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add the YAML-deserializable section page-style property.
- `src/MasonicCalendar.Core/Renderers/SectionRenderers/SectionRenderer.cs`
  - Apply a section's configured page-style name to its wrapper.
- `src/MasonicCalendar.Core/Renderers/SectionRenderers/StaticSectionRenderer.cs`
  - Pass the configured page style to the shared wrapper for static sections.
- `src/MasonicCalendar.Core/Renderers/SchemaPdfRenderer.cs`
  - Generate the configured zero-margin, no-footer named `@page` CSS rule.
- `_work-plan-20260831.md`
  - Record approval and validation.

## Scope

- Only `back_cover` receives the new page style.
- Keep the existing front-cover `@page :first` behavior unchanged.
- Validate using `-section static -showbleeds`, confirming the back-cover image reaches the crop-mark trim boundary and shows no footer page number.

## Risks

- Named-page behavior is implemented by Paged.js, so proof validation must inspect the final paginated back-cover page rather than only source HTML.

## Validation

- Ran `dotnet run -- -template master_v1 -output html -section static -showbleeds` successfully.
- Verified Paged.js applied `pagedjs_full_bleed_no_footer_page` to the final page.
- Confirmed the front and back cover images have identical 419.5 px x 582.0 px proof dimensions and identical 22.7 px offsets within their pages.
- Confirmed the back-cover footer content is empty.

## Rollback Strategy

Remove the `back_cover` page-style setting and its supporting page-style rendering code. The current normal-margin, numbered behavior returns without affecting other sections.
