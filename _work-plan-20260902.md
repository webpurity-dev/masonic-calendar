# Work Plan - Configurable Past Head Ordering

**Date:** 2026-09-02  
**Approval status:** Approved by user  
**Implementation status:** Complete

## Configuration Strategy

Add an optional `sort_by` property to each unit past-head data source definition. Supported values for this change are `YearInstalled` (default) and `PosNo`. Configure only `document/data_sources/ros_data_source.yaml` with `sort_by: "PosNo"`.

## Files Affected

- `document/data_sources/ros_data_source.yaml`
  - Select position-number ordering for ROS past heads.
- `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs`
  - Add the YAML-deserializable optional sort property to `DataSourceDefinition`.
- `src/MasonicCalendar.Core/Loaders/SchemaDataLoader.cs`
  - Pass the past-head configuration into deduplication and apply the configured ordering while preserving the current default.
- `_work-plan-20260902.md`
  - Record scope, validation, and implementation status.

## Scope

Change ordering only for `unit_past_heads`. Keep all other data source behavior unchanged. Missing or unrecognized configuration will retain the existing `YearInstalled` ordering.

## Approach

1. Add `sort_by: "PosNo"` to the ROS mapping.
2. Add an optional `SortBy` property to `DataSourceDefinition`.
3. Select `PosNo` ordering when configured; otherwise use `YearInstalled`.
4. Run focused tests and a build.

## Risks

- An incorrect sort key could silently change ordering. The implementation will recognize only the explicit `PosNo` value and retain the existing default for all other values.
- Null position numbers will sort after configured numeric positions.

## Rollback Strategy

Remove the ROS `sort_by` entry and the associated model/loader changes. Existing ordering then remains unchanged.
