# Typography Scale Rollout Plan

## Scope

Introduce a YAML-driven A6 typography scale for core calendar content. The approved reading target is 8 pt standard body text, 7 pt dense tabular content, and 6 pt secondary text. The rollout covers unit pages, contents, officer lists, succession lists, meeting tables and calendars, and membership summaries/statistics.

Extend `-section` to accept an inclusive range in the order declared by `master_v1.yaml`. For example, `-section cover-sgc_officers` will render `cover`, every intervening configured section, and `sgc_officers` as one document.

## Configuration Strategy

Store the semantic scale in `document/master_v1.yaml` under the existing `global_styling.fonts.sizes` mapping. Proposed values:

```yaml
global_styling:
  fonts:
    sizes:
      body: "8pt"
      dense_table: "7pt"
      secondary: "6pt"
```

`FontConfig.Sizes` already deserializes this mapping. `SchemaPdfRenderer` will generate CSS custom properties from the mapping, allowing templates to use semantic values such as `var(--font-body)`, `var(--font-dense-table)`, and `var(--font-secondary)`. No display value will be hardcoded in C#.

    The completed scale also defines `title: "14pt"`, `heading_primary: "12pt"`, and `heading_secondary: "10pt"`. These control document titles, `heading1`, and `heading2` respectively.

## Approach

1. Add and deserialize the scale through the existing font configuration.
2. Thread the configuration into the relevant Scriban models without changing unrelated template inputs.
3. Replace inline font sizes in the listed core templates with semantic typography values.
4. Preserve title sizes unless a proof identifies a hierarchy issue.
5. Render PDF proofs for a dense unit, officer list, contents, meeting table, and membership summary; compare legibility, wrapping, and page breaks.
6. Interpret `-section <start>-<end>` as an inclusive range of exact section IDs in their YAML declaration order. Exact section IDs continue to take precedence over section-type selection.
7. Reject unknown endpoints and reversed ranges with a clear CLI error. Render `cover-sgc_officers` as the representative range proof and verify that the first and last requested sections are present, in order, with no sections outside the range.

## Risks

- Increasing dense content to 7 pt will increase page count and may create additional page breaks.
- Fixed-width tables may wrap longer names, ranks, and unit titles; the proof set must include the densest known examples.
- Some meeting-table styles may need a separately configured compact mode if 7 pt does not fit the twelve-month grid.
- Section ranges rely on `-` as a separator; this is valid for the current underscore-based section IDs. Any future section ID containing `-` would need an explicitly chosen alternative range syntax.

## Rollback Strategy

Revert the semantic template references and remove the YAML scale. Existing inline sizes remain available in version control for precise rollback.

## Print Proof Overlays

### Scope

Separate the proof overlay modes into three independently composable CLI flags:

- `-showbleed`: draw a dotted line at the configured 3 mm trim inset, making the bleed boundary visible.
- `-showprint`: draw only configured crop marks at the trim corners.
- `-showmargins`: draw a red dotted rectangle at the configured alternating page margins.

All overlay lines will be 0.25 px wide. The 3 mm trim inset, crop-mark length, corner gap, and crop-mark color remain sourced from `master_v1.yaml`. The red margin color and 0.25 px proof line width will be added to the existing YAML `crop_marks` configuration so no display settings are hardcoded.

### Files Affected

| File | Change | Why |
|---|---|---|
| `document/master_v1.yaml` | Add YAML proof-overlay settings for line width and margin color. | Retains the project's configuration-first display policy. |
| `src/MasonicCalendar.Core/Domain/PageMargins.cs` | Add properties for the YAML proof-overlay settings. | Deserializes the configured line width and margin color. |
| `src/MasonicCalendar.Console/Program.cs` | Parse the three proof flags, pass them to the renderer, and identify them in help/output filenames. | Makes each proof overlay available independently through the CLI. |
| `src/MasonicCalendar.Core/Renderers/SchemaPdfRenderer.cs` | Generate independent bleed-boundary, crop-mark, and alternating margin CSS overlays. | Shows each production boundary accurately and allows flags to compose. |

### Approach

1. Add `proof_line_width: "0.25px"` and `margin_color: "red"` to the existing YAML crop-mark configuration.
2. Use `trim_inset` for the dotted `-showbleed` rectangle.
3. Use `mark_length`, `corner_gap`, and `color` for the `-showprint` crop marks only.
4. Use the existing alternating YAML page margins directly in side-specific CSS `inset` declarations for `-showmargins`.
5. Apply first-page margins to the cover proof, and preserve normal output when no proof flag is supplied.
6. Render both a single-page cover and a multi-page body proof with all three flags to verify positioning and composition.

### Risks

- The first-page cover margin is configured as zero, so its margin rectangle will align with the media edge.
- Paged.js class names must match the generated left/right/first page wrappers; a one-page cover and a multi-page body proof will verify this.

### Approval Status

Approved and implemented on 2026-09-04.

### Validation

## Static Template Typography Standardization

### Scope

Replace remaining hardcoded active font sizes in static page templates with the existing YAML typography roles. Normalize primary title margins to `margin: 0 0 4px 0` so static titles have the same spacing below them. Preserve intentionally compact table content through `dense_table` and footnotes through `secondary`.

### Role Mapping

| Content | Typography role | Title margin |
|---|---|---|
| Primary page title (`h1`/`h2`) | `var(--font-title)` | `0 0 4px 0` |
| Secondary/subsection heading | `var(--font-heading-secondary)` | Preserve local compact subsection margin where it affects legal content flow |
| Normal prose | `var(--font-body)` | Existing paragraph spacing retained |
| Dense tables/listings | `var(--font-dense-table)` | Existing table spacing retained |
| Captions, legal notes, and supporting text | `var(--font-secondary)` | Existing local spacing retained |

### Files Affected

| Templates | Why |
|---|---|
| `document/templates/foreword.html`, `freemasons-charity.html`, `copyright.html`, `data-protection.html`, `notes.html` | Core static prose, notices, and reference pages still use hardcoded typography. |
| `document/templates/companion/*.html` | Static order introduction pages require a consistent title/body/subheading hierarchy. |
| `document/templates/craft/*.html` | Static Craft reference pages mix hardcoded title, body, dense table, and footnote sizes. |
| `document/templates/royalarch/associated-chapters.html` | Static associated-unit listing retains hardcoded title/body sizes. |
| `document/templates/photos/*.html` | Static photo captions will use body/dense-table roles while retaining their established visual hierarchy. |
| `document/templates/_placeholder.html` | Keeps the sample static template consistent with production static pages. |

Cover templates are excluded because they are full-bleed artwork rather than normal static reading pages.

### Approach

1. Replace active inline point values with existing semantic variables only; do not add new font sizes.
2. Normalize only primary page-title margins to `0 0 4px 0`.
3. Preserve local spacing on compact photo captions, legal subsections, tables, and body paragraphs to avoid unnecessary layout changes.
4. Render the static section with `-showbleed -showmargins` and review representative prose, introduction, reference-table, photo, and legal pages for clipping or unexpected extra pages.

### Risks

- Raising the data-protection policy from 6 pt to the 8 pt body role may increase its page count.
- Static pages using compact dense tables may wrap differently at 7 pt.
- Long introduction titles may wrap after title-size normalization and need visual proofing.

### Approval Status

Approved and implemented on 2026-09-05.

### Validation

- Verified the final active-size inventory; all migrated active static typography uses `var(--font-...)` roles.

## Honorary Member Rank Wrapping

### Scope

For honorary members, render the rank on a new line when either multiple ranks are deliberately displayed or the rank text exceeds the configured threshold. The requested threshold is 10 characters. For example, `Barnes, K H,` remains on the first line and `PProvGM (Dorset)` appears below it.

### Configuration Strategy

Add the following under `ui_preferences` in `document/master_v1.yaml`:

```yaml
honorary_members_display:
  rank_wrap_threshold: 10
```

The rule is calculated in C# from raw rank values and the configured threshold, then supplied to the template as `rank_on_new_line`. The template will not parse formatted display strings.

## Deterministic Table Page Limits

### Scope

Force page breaks and repeat table headings for meeting tables, membership-statistics tables, and the all-units index. Configure a maximum of 25 units per page for meeting tables and membership statistics, and 44 units per page for the all-units index. Increase the meeting-table title spacing above the table where the new page layout permits it.

### Configuration Strategy

Add shared settings under `ui_preferences` in `document/master_v1.yaml`:

```yaml
table_pagination:
  meetings_table_rows_per_page: 25
  membership_statistics_rows_per_page: 25
  all_units_index_rows_per_page: 44
  meetings_table_heading_spacing: "12px"
```

The values are read by the existing UI-preferences path. Each renderer will chunk rows before rendering; templates will loop over page groups, rendering a full heading and table per group. The first meeting-table page receives the configured title spacing, and continuation pages retain a compact repeated table heading.

### Files Affected

| File | Change | Why |
|---|---|---|
| `document/master_v1.yaml` | Add table pagination limits and meeting-title spacing. | Keeps all limits and display spacing configurable. |
| `src/MasonicCalendar.Core/Loaders/DocumentLayoutLoader.cs` | Add `TablePagination` configuration model. | Deserializes the YAML settings. |
| `src/MasonicCalendar.Console/Program.cs` | Make table-pagination settings available to relevant renderers. | Applies the layout configuration to rendering. |
| `src/MasonicCalendar.Core/Renderers/SectionRenderers/MeetingsTableSectionRenderer.cs` | Split meeting rows into configured 25-row page groups. | Prevents browser-chosen breaks. |
| `src/MasonicCalendar.Core/Renderers/SectionRenderers/MembershipStatisticsSectionRenderer.cs` | Replace fixed two-page split with configured 25-row page groups. | Supports deterministic repeatable pagination for any number of rows. |
| `src/MasonicCalendar.Core/Renderers/SectionRenderers/TocSectionRenderer.cs` | Split all-unit index entries into configured 44-unit page groups while preserving their section grouping. | Forces predictable index pages. |
| `document/templates/_data-driven/meetings-table-page.html` | Render repeated table headings for each meeting page group. | Keeps month and year labels visible on continuation pages. |
| `document/templates/_data-driven/membership-statistics-page.html` | Render repeated column headings for each statistics page group. | Keeps statistical columns visible on continuation pages. |
| `document/templates/_data-driven/unit-index-page.html` | Render repeated index title/table headings for each 44-unit page group. | Keeps index context visible after forced page breaks. |
| Focused renderer tests | Add checks for configured chunk sizes and continuation-page headings. | Prevents regression in deterministic pagination. |

### Approach

1. Preserve the current table body and header markup, extracting repeated structures only where necessary for a page-group loop.
2. Count meeting-table units, not expanded recurrence rows, when applying its 25-unit limit; all rows belonging to one unit remain together.
3. Chunk membership-statistics data at 25 rows per page, rendering totals only on the final page.
4. Chunk the all-units index at 44 units per page without splitting its two-column pairs across a page boundary.
5. Render representative meeting, statistics, and all-units index PDF proofs with `-showmargins` to confirm forced page starts, repeated headings, and no clipping.

### Risks

- Meeting tables can contain multiple expanded recurrence rows per unit, so a 25-unit group may still exceed one physical A6 page; this must be checked using a dense meeting section.
- Preserving all-units section headings may result in fewer than 44 entries on a page when a group boundary or heading occurs.
- Repeated full page titles on continuation pages reduce available table height; the first title spacing will be configurable to tune this after proofing.
