# Digital Margin Mode Plan

**Approval status:** Approved 2026-09-09

## Scope

Add a `-digital` render mode for screen-first output. It retains the existing A6-plus-3mm-bleed page size and top/bottom margins, but removes alternating binding-gutter behavior by applying the smallest configured left/right margin to both sides of every content page.

## Configuration Strategy

Store the policy in `document/master_v1.yaml` at `page_margins.digital_mode.equalize_side_margins`. The setting is deserialized by a small `DigitalModeMargins` domain class so templates can opt into the behavior without source changes.

## Changed Files

- `document/master_v1.yaml`: enable the digital equal-side-margin policy beside the existing page-margin configuration.
- `src/MasonicCalendar.Core/Domain/PageMargins.cs`: model the YAML digital-mode policy.
- `src/MasonicCalendar.Console/Program.cs`: parse `-digital`, pass it to the renderer, identify the output, and document the option in CLI help.
- `src/MasonicCalendar.Core/Renderers/SchemaPdfRenderer.cs`: apply equal side margins to right, left, and standalone-content first pages when the CLI mode and YAML policy are enabled.

## Approach

1. Add the YAML switch and deserialization model.
2. Pass the `-digital` flag into `SchemaPdfRenderer`.
3. Select the smaller of the configured side margins for every non-cover page rule while preserving page size, bleed, vertical margins, footers, and cover behavior.
4. Render a representative HTML section with `-digital` and verify the generated CSS has `6mm` on both left and right sides while retaining `111mm 154mm` page size.

## Risks

Margin values are CSS lengths. The implementation will compare only matching numeric units and fall back to the configured side margin if the values cannot be compared safely.

## Rollback

Run without `-digital`, or set `equalize_side_margins: false` in YAML. Both retain the existing print-margin behavior.
