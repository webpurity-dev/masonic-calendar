# Officer Duplicate Validation Plan

## Configuration Strategy

Use the existing data-source YAML `Reference`, `Position`, `Name`, and `UnitId` field mappings already read by `validate-output.ps1`. No labels, field names, or duplicate rules will be hardcoded beyond the existing officer-section convention.

## Files Affected

| File | Change | Why |
|---|---|---|
| `scripts/validation/validate-output.ps1` | Validate duplicate officer rows using the configured unit, name, and position columns. | A person may legitimately hold multiple offices, but must not appear twice in the same office for one unit. |
| `_work-plan-20260910.md` | Record scope, approach, risks, and validation. | Required plan for a non-trivial repository change. |

## Scope

- Retain duplicate `UniqueRef` warnings for non-officer membership sections.
- For officer sections, warn only when a non-vacant row repeats the same configured `UnitId`, `Name`, and `Position`.
- Do not make duplicate warnings fail validation.

## Approach

1. Replace the officers-section skip with a composite duplicate key based on the YAML-mapped unit, name, and position columns.
2. Ignore vacant or positionless officer rows, consistent with existing validation behaviour.
3. Run the focused validation script and verify it completes without PowerShell errors.

## Risks

- Older data-source YAML files without a `Position` mapping cannot establish an officer-office key; these rows will be skipped rather than treated as duplicates.
- This validates duplicate source CSV rows only; it does not modify CSV data or rendered output.

## Rollback

Revert the targeted duplicate-grouping block in `scripts/validation/validate-output.ps1`.

## Validation

Initial validation identified that reference-and-position comparison did not detect duplicate appointments with separate `Unique Ref` values. The check now uses unit, name, and position.

- Royal Arch unit 665 has three confirmed duplicate appointments with distinct references: `Hunt, J R` as `MEZ`, `Maxwell, C J` as `H`, and `Gibbons, R W` as `J`.
- PowerShell diagnostics reported no errors, and `git diff --check` reported no whitespace errors.
- The requested Royal Arch `-Render` validation run was skipped, so executable confirmation of the warnings remains pending.
